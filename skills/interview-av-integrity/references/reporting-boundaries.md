# 報告境界

## 推奨する論理順序

1. 観測: 何が映像・音声に見えたか
2. 測定: どの時刻・品質・不確実性で測ったか
3. 比較: 同じ候補者の参照例、他話者、epochとの差
4. 仮説適合性: どの仮説と整合し、何でも説明できるか
5. 原因: この録画だけでは識別できないもの
6. 次の確認: 制御された再面談や適法な本人確認

## 表現

使う:

- 「指定窓の高品質な可視フレームでは、明瞭な両唇接触を確認できなかった」
- 「音響開放は可視的接触より先行して見える」
- 「候補者の閉鎖あり参照例では、接触が確認できた」
- 「この所見は代理発声仮説と整合し得るが、固定A/V offset、隣接音素、会議処理等を排除しない」

避ける:

- 「本人は発音していない」
- 「別人の声である」
- 「口パクが確定した」
- A/V所見から人物属性、所在地、所属、意図を推定する表現

「検出できなかった」と「存在しなかった」を区別する。24fpsでは1 frameが約41.7msで、短い閉鎖がフレーム間へ隠れ得る。no-contactの確度は、可視品質、複数評価者、参照例、隣接音素追跡と一緒に示す。

## 契約・採用への接続

本分析を単独の採否根拠にしない。必要なら全候補に一貫した手続で次を行う。

- ランダム語・数字列・動作を含むライブ再面談
- 別端末・別回線・背景処理offでの同期確認
- 画面共有を伴うライブ技術課題
- 適法な本人、就労資格、契約主体、支払先の確認
- 最小権限・sandbox・短期有償trial

外部共有前に、顔、声、氏名、メール、電話、絶対パス、発言内容の必要性を再確認し、アクセス・保存期間を制限する。
